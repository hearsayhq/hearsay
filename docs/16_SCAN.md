# Scan of public MCP servers

Aggregates only (FR-062, D-024): no repository or team names, no issues or pull requests to anyone. Servers were pinned to a commit, built and run locally in containers with no network beyond Hearsay and no credentials. Servers listed only were read (handshake and `tools/list`) and never called. In calls mode, each tool the server marks read-only that needs no arguments was called three times: twice to see that it reads the same, once to judge the reply as spoken. The two groups below are never added together.

What this covers: the declared surface (`hearsay lint`) and replies of read-only tools. Checks that need a suite (misheard values, consent, mandates, latency of real calls) did not run, so a server without findings here is not shown to be voice-ready.

## Notes

- Generated by `scripts/scan/aggregate.ts` from the second run on 30 Sep 2026: 40 servers, of
  them 31 Alexa+ add-on servers from hackathon entries and 9 general MCP servers. The first run
  that day is not used. In list mode it called read-only tools through the
  `lint.destructive_annotated` probe, which the owner had approved for `tools/list` only (R-17).
  The harness was fixed (`callTools: false`, one bearer or none, Host as a local client sends it)
  before the second run.
- Start commands come from each README. Where a README left something out, the smallest change
  that let the server start was used (one general server: a flag for its in-memory database).
- The one `protocol.version` warning among the add-ons comes from a server that accepts a single
  MCP session per process: the second connection, the probe offering 2025-03-26, got HTTP 404. It
  is counted as the check reports it, but it says more about sessions than about the version.
- Servers listed only cannot show `speak.*` findings, so the row "Can I listen to this?" for the
  add-ons rests on the 5 servers whose read-only tools could be called without arguments.
